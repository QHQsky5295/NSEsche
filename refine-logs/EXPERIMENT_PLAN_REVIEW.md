## 1. 核对后的四个结论

1. 缺少旧逐次数据时，旧柱图不能补出合法的误差棒；主比较必须重新采集逐 run 数据。但收敛、开销、分类指标应尽可能同时从这批运行采集，不分别重跑完整主矩阵。

3. B0 历史审计发现旧图缺少唯一的 seed/config/binary 绑定，历史批处理与导出还存在重复空 seed、同键覆盖问题。部分旧 Excel 常量可找回，但不等于找回了 20 次独立运行。不能承诺旧柱逐值复现。

## 5. 主指标、负载与旧图衔接

### 5.1 固定旧定义，不以旧柱作为搜索目标

主比较保持 20-node homogeneous、CPU 150、memory 5000、1 frame = 1 ms，以及冻结的函数/DAG生成规则。异构保持同均值与 CPU/memory 的 30%/25% 标准差设置，具体采样和非正容量处理须固定。

原论文的 8–10 Gbps 与历史实现记录的 8000–10000 MB/s 存在量纲疑点；逐层核实数据量与传输时间后披露准确单位。不能一边使用旧数值，一边继续声称不同的物理带宽。

主比较到达及主测量窗口固定为 1000 ms。请求率以 tape 事件数/到达时间计算。已有新协议约 1.9k/2.6k/7k req/s 是重新声明的工作负载设置，不是旧稿 15k–70k high 的逐值复现。不再为了获得好柱高在 6k/7k/8k 之间挑选。

同一主窗口计算：

- throughput：窗口内完成的 application/DAG requests / 1000 ms；另报 req/s，图轴可写 10³ requests/s。
- cost：截至窗口末的全平台累计资源成本 / 窗口内完成数。分子包含未完成工作的耗费，不只统计成功请求消耗。
- latency：该窗口内已完成请求的端到端时延；分项检查不能遗漏或重复计算数据等待。
- QPR：逐 run 按原式 throughput/(cost × latency) 算，再统计 20 个 run，不能由三个跨 run 均值拼出一个 QPR。

函数任务数与完成工作流数分别命名；“function requests”不能不加解释地指代两者。QPR 是复合仿真效率指标，不是货币收益，也不由社会效用高自动推出。

若零完成导致 cost/latency/QPR 不可定义，保留 run、完成率和 undefined 原因；不能只删除这些 run 后报告完整总体的 QPR 均值，不能用小常数补分母。这类真实结果与 crash/截断不同。

### 5.2 Drain 单独报告

主柱仍取固定 1000-ms 口径。到达结束后用预先冻结的 drain 预算追踪同一 arrival cohort，报告完成率、未完成数、尾时延及删失。

沿用 P6 的由输入工作量计算且最高 200k frames、30 min/run 的有限预算，不宣称它是数学完成上界。到预算仍未完成是真实结果，不更换输入。不能把 fixed-window throughput 与 drain 后 latency/cost 拼成“更好”的主 QPR。

### 5.3 新旧对照表

每个旧图存 old_pdf_alignment.csv：旧值来源（工作簿常量/像素估读/缺失）、新均值和 CI、单位、版本、协议差异及解释。旧值没有原始重复数据时不添加虚构 CI。

超出旧柱 ±15% 仅触发诊断，不能作为删 seed、削弱 baseline 或不断回归旧柱的验收条件。单位或共同代码确有错误才重算/重跑受影响块；找不到可证错误就如实说明重评估差异。

## 6. 优化 NSESche 的规则

目标仍是尽可能同时改善 throughput 与 QPR，但优化对象是实现/参数，不是正式数据的保留规则。

1. 用完整开发 bank（建议 10 个配对 seeds）分析请求完成链、排队、冷启动、数据等待、成本与效用各项。单个 seed 可用于复现原因，不能把“挑出来的最优 seeds”当总体评估。
2. 优先尝试有日志依据的缓存/增量计算、确定性初始化和顺序、合法等效用 tie-break、参考构建质量及论文已有参数。每次一个明确假设，记录全 bank 的正负效果；不承诺每次修改都改善。
3. low 的原参数中心为 (0.6,0.5)，middle/high 为 (0.5,0.6)。允许按负载在开发集选择已披露参数；最终用一套算法代码和预先冻结的参数映射。不能隐藏“遇到某 seed/某负载改用另一个 scheduler”的分支。
4. 严格 Eq.(15) 不能变成“容忍 5% 效用损失来挑更快节点”后仍称完全相同算法；调用其他 baseline 作为隐藏 expert 同样不是实现级修补。
5. 不通过任意平移/放大效用使参考转正或 PoA 靠近 1。这样的操作即使不改变某一内层 argmax，也会改变社会差距和外层反馈含义。
6. 正式前一次冻结所有负载的配置，使用未见的 20 个配对 seeds，按 low → middle → high 执行；所有有效 run 保留。不能删掉未胜 baseline 的 seeds 再补到 20 次。
7. 单个机制假设最多三个开发候选，失败先解释而非继续加阈值。正式确认失败后保留全批，不反复试正式集直到赢；若确需重新开发，要明确新版本、额外预算、既有确认次数和新的独立确认安排。

区分两种状态：
- 数据完成：规定样本、QC、口径和证据链齐全，允许冻结保存，即使效果不好。
- 优势获支持：预定比较上确有优势且 CI/检验支持相应强度的表述。

均值第一但 CI 跨零只能写观察到较高均值，不能写显著优越。没有在所有负载第一不自动等于论文不能写；应回到原稿的具体负载和权衡主张。

### 8.1 Burst

固定 1000-ms 到达窗与总请求/DAG multiset，不同形状仅重排到达时间。5×/50ms 单峰、3×/200ms 持续峰、四次4×/50ms脉冲；倍率相对于配对稳态平均率。为了保持总量，非峰背景率分别约为稳态的 0.7895、0.5、0.25；以整数事件数校验实际峰率。开始时间、离散取整及 seed 在结果产生前固定。

报告 queue 峰值/面积、恢复、throughput 时间序列、drop/reject、p95/p99、SLA和未完成。恢复阈值使用独立校准的配对稳态 queue/tail 阈值并连续满足 50ms；明确零基线的处理，不能使用 110%×0 而不加解释。未恢复按右删失报告，不填一个看似合理的恢复时间。

### 8.2 QoS / 特征

函数类别在输入生成时固定，不能看到完成情况再分类。分类统计以 function invocation 为单位，全局 DAG 端到端指标另列；共享费用按事先声明且能核对总额的规则分摊。SLA阈值在独立校准输入上冻结，不按哪个方法更好选择阈值。Jain index 与最差10% satisfaction一并报告。

hri 验证其资源平衡含义，不伪装绝对负载预测量；hnd 对真实 transfer/data-wait 做关联；hpi 是算法区分因子，不要求它与物理通信量相关。hpi 的价值用仅关闭该因子的消融与同分/放置分散统计验证。相关性按 run/seed 分组，不把同 run 的大量函数当独立重复；关联不直接证明因果。

### 8.3 Reference / 收敛 / PoA

- 记录每个状态键、更新触发、unique states、cache命中、build wall/CPU/RSS/SA次数、文件大小、加载和lookup耗时。reference 必须绑定实际 workload/resource/price/candidate/method 状态，不只按“high”名称复用。
- build/replay 必须动作/状态匹配。用评估轨迹预构建的精确状态表只能支持“该轨迹的离线预计算回放”，不等于对未知 workload 的零成本在线估计。不能只展示 replay 查表时间，却隐去首次状态计算成本。
- 若稿件要保留“未知负载直接在线适用”主张，需要另外验证未见 profile 上预建参考覆盖/误差与 miss 回退；否则明确收窄为离线校准评估。此处是声明边界，不通过藏起成本解决。
- 保留正、零、负、缺失、估计低于当前值等全部比例；不计算无效比值，不静默截断负gap使曲线好看。
- 内层 assignment 稳定与外层 placement 稳定分别报；cap终止不等于收敛。已有 P1 的97.396%外层稳定率不写成100%或全双循环定理。
- exact PoA用同一固定博弈的最优福利和最差PNE，仅在适用的正福利域解释比值。300状态的最大值不是所有规模上界。大状态只称估计福利差，不称 exact PoA。
- 跨方法福利尽量在同一冻结状态、同一player/候选集、同一基础价格下复评。不同方法经历不同请求集合，不能直接把不同窗口福利均值当等价的同状态比较。

### 8.4 近邻对照的资格风险

R3-4 不是只补 related work 就能完整回应。保留两个近邻对照名额，但须先确认确实保留了已发表方法的核心决策与适配边界。自建 CP-BR 可以作为机理对照，不能冒充一个已发表系统或独自替代近邻工作比较。

原计划提到的 OnSocMax 针对可分割工作量、时空资源与社会福利，不能不加说明就当成原生不可分DAG放置算法。其改编是否足够忠实须做源算法—适配—测试对照；不合适则在看正式结果前选更贴近的已发表方法，不为了易胜保留弱化版本。

来源：[OnSocMax 原论文](https://dsg.tuwien.ac.at/team/sd/papers/Journal_paper_2025_S_Dustdar_Online_Workload.pdf)。目前不将这两个 comparator 标为实现资格已完成。

## 9. 最省时间的冻结、统计与存储方式

### 9.1 baseline 复用

baseline 不需要随每次 NSESche 调参重跑。冻结一个有效的完整配对对照 bank；仅当 tape、公共runtime/HPA/冷启动/候选集/队列、配置、测量定义和baseline自身版本都相同，才复用。

只改 NSESche → 只补跑其受影响的正式/开发数据与 reference。
改公共平台 → 所有受影响的方法必须在新协议上重新取得对照。
只改绘图 → 从同一原始数据重新导出。
已冻结原始数据永久保留；“保留不动”不意味着它自动适用于后来改变的方法。

### 9.2 样本和统计

旧实验使用20个配对独立seeds；新增burst明确为10个，不再笼统声称所有实验都是20次。开发/正式bank不相交，各方法输入配对；方法比较在run层计算配对差值、95%CI、双侧paired permutation与预定family的Holm校正。p95/p99先在每run内计算，低样本尾分位须报告样本量。BCa不稳定/退化时明确报告方法限制，不制造CI。

主图叠加CI/必要seed点；均值排名、效应量、win/tie/loss和副指标一起解释。热图使用全部run的预定汇总，不从中挑一张最有利的“代表性”轨迹；展示单条轨迹时使用结果前固定的seed。

技术失败仅包括真实 crash、IO、截断、身份不匹配或计数不变量错误等。同 seed/tape/config/binary 最多重试三次并留失败记录。低吞吐、高延迟、合法timeout、未恢复、非收敛、不显著均不是可删样本。

### 9.3 运行预算

正式计划上限2520 online runs；原有合格同身份结果逐项抵扣。另计：
- P6 pilot90 + 确定性重复1；
- 开发baselines最多9×3×10=270；NSESche中心30，每个全三负载候选另30，单负载候选10；
- reference build、模型训练/SLA校准和轻量单元验证，单列账本，不假装免费；
- 不重复已经保留的P1 300个精确状态。

用pilot实测的各负载median/p95运行时间与reference成本给出预计小时数；尚无依据承诺36—48小时完成。调度开销测量避免与大规模并发争用混在一起。顺序运行当前论文组，先做低负载正确性和开发判断，不提前启动昂贵后续主矩阵。
